# 星界工坊 · 战术星图

13 个关卡从一开始即可选择。编号代表建议挑战顺序，旧存档也不会锁住关卡。前12关用更少、更大的砖块，把难度放在回球角度、装甲入口、反应芯弱点与加速后的接球判断上。

普通砖一击即碎；银蓝装甲挡住穿透火球，通常需要两次命中；金色反应芯被光球或超新星直接击破后对周围八格造成一点伤害；薄荷色加速砖会提高撞击它的那颗球的速度。反应冲击不会触发下一枚反应芯的连锁爆炸。所有砖块都可摧毁，没有永久障碍，也没有十血砖墙。

| --- | --- | --- | --- |

## 编辑与生成

`tools/generate-levels.cjs` 生成前12关，并读取 `levels/preserved/lu-yuan-easter-egg.json` 原样保留第13关的砖阵与玩法参数。该资源来自原始提交 `09cc7ac`，请勿用普通战术布局替换这份个人彩蛋。生成无需第三方依赖：

```sh
node tools/generate-levels.cjs
```

生成器使用确定性坐标与几何谓词，写入 `levels/level-NN.json`，验证坐标、重复位置、角色血量、颜色、砖区高度和总量预算，并输出每关的角色数量、总血量与基础参数。编辑 JSON 后若需要保留修改，应同步修改生成器，否则下次生成会覆盖。

现代版的 `web/game/build-legacy.cjs` 与旧版 `build.js` 都读取同一目录。`npm run dev`、`npm run build` 和 `npm test` 会更新现代关卡模块。

## 数据格式

```json
{
  "name": "关卡2 - 光子花园",
  "difficulty": 1,
  "briefing": "金色反应芯需要两次命中；优先击破它，周围冲击会拆掉邻砖。",
  "gridWidth": 24,
  "gridHeight": 20,
  "ballSpeed": 332,
  "paddleWidth": 94,
  "lives": 3,
  "bricks": [
    { "row": 1, "col": 2, "hp": 1, "color": "#61dce9", "kind": "normal" },
    { "row": 1, "col": 3, "hp": 2, "color": "#b8ccf4", "kind": "armor" },
    { "row": 2, "col": 4, "hp": 2, "color": "#ffc971", "kind": "reactor" },
    { "row": 3, "col": 4, "hp": 1, "color": "#80efc8", "kind": "accelerator" }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `name` | 显示名称 |
| `difficulty` | 可选的建议难度，整数 1–5；不控制关卡解锁 |
| `briefing` | 可选的简短战术提示，在游戏区域之外展示 |
| `gridWidth` / `gridHeight` | 网格列数与行数，非像素尺寸 |
| `ballSpeed` | 初始球速，逻辑像素 / 秒 |
| `paddleWidth` | 挡板基础宽度，逻辑像素 |
| `lives` | 初始生命数 |
| `bricks[].row` / `col` | 从 0 开始的整数坐标，同一位置只放一个砖块 |
| `bricks[].hp` | 普通砖、加速砖为 1；反应芯为 2；本套装甲为 2 或 3 |
| `bricks[].color` | 可选的十六进制色值，保存作者指定的颜色 |
| `bricks[].kind` | 可选的 `normal`、`armor`、`reactor` 或 `accelerator`；旧数据缺省按既有规则兼容 |

## 几何与可玩性约束

游戏使用 `375 × 667` 逻辑画布。左右各留 10 像素，砖缝为 2 像素，砖块是正方形。对于列数 `W`：

```text
砖格步长 = 357 / W
砖块边长 = 357 / W - 2
砖块顶边 = 90 + row × 357 / W
砖块底边 = 90 + (row + 1) × 357 / W - 2
```

前12关砖区底边约为 356–390 像素，与初始挡板中心 `y = 567` 保留至少 177 像素。留空一列产生的净通道为 15.7–16.9 像素，可以通过正常球；主入口通常留空两到三格。普通 2 像素砖缝不算通路。

前12关的生成预算为每关 90–220 块砖、平均血量 1.25–1.72、单砖最高 3 HP、砖区底边不超过 400 像素。实际关卡采用更小范围；这些上限用于防止后续编辑变成密集消耗战。仍应结合完整通关模拟与真人触屏试玩检查反弹死角和难度，不能把完美追踪机器人的通关率当作普通玩家胜率。

第13关不受普通战术关卡的数量、平均HP及砖块角色预算约束，但仍进行坐标、重复位置、HP与砖区高度检查。重新生成不得改变原始文字轮廓。
